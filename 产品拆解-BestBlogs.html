BestBlogs.dev —— AI 驱动的个性化高质量阅读工作流

不是又一个内容聚合器，也不是追热点的推荐流。它的核心命题是：真正稀缺的不是内容，而是高质量信息的发现、判断、压缩与持续跟踪能力。用 AI 做规模化质量判断 + 人工精审建立公共质量池，再叠加个性化工作流驱动留存与付费。

① 它到底是什么

每天从 600+ 订阅源自动抓取文章、播客、视频、推文（日均 1000+ 篇），经大语言模型六维评分、摘要、翻译后，按每位用户的兴趣标签生成个性化早报。一句话定位：公共策展建立信任，个人工作流驱动留存，可调用基础设施打开天花板。

② 解决什么问题

发现与判断的鸿沟

高噪音环境里，判断一条内容是否值得读的成本，已经高于获取它的成本。多数产品要么只搬运，要么把相似热点推给所有人。

吸收效率的瓶颈

长内容太多、时间太少。没有压缩和优先级排序能力的产品，本质在浪费用户最稀缺的资源——注意力。

阅读无法沉淀为知识

阅读停留在"看过"，缺少回顾、积累与复用。碎片化阅读没有跟踪机制，读过的好内容最终遗忘。

核心信念（决定产品形态）：「最好的阅读产品让你读得更少，而不是更多。」—— 因此他们拒绝优化阅读时长、内容数量、无深度日活这三个指标，北极星是"深度阅读闭环率"。这与今日头条类产品的目标函数根本对立，是产品哲学层面的差异。

⑥ AI 分析管线（真正的护城河）

这是产品最值得复刻、也最难复刻的部分。早期他们用一个大而全的提示词做摘要+标签+评分+翻译，结果：摘要遗漏信息、标签不统一、评分难调、翻译生硬。后来拆成 Dify Workflow 多子流程，效果与可维护性大幅提升。

三大子流程

流程 A
文章初评
中英分模型 + CO-STAR 提示词，剔除低质/营销内容
流程 B
文章分析
分段→汇总→打标→评分→反思→优化
流程 C
结果翻译
识别术语→初译→检查→意译

流程 B 内部节点（核心）

  • 长度判断：>6000 字符则分段处理（迭代 + 变量聚合），否则全文分析，避免遗漏段落关键信息
  • 内容生成：一句话总结 + 摘要 + 关键词 + 主要观点 + 金句
  • 领域划分与打标：主题/技术/领域/应用/产品/公司/平台/名人/趋势
  • 多维评分：内容深度、写作质量、实用性、相关性等
  • 检查反思：LLM 扮演"技术文章评审专家"，按全面性/准确性/一致性审查上述输出
  • 优化改进：基于反思结果二次确认格式与语言，输出最终分析 + 更新原因

复刻要点：不要把摘要/打标/评分/翻译塞进一个提示词。拆成"单一职责节点 + 检查反思 + 优化改进"的链路，每个节点可独立调试、独立换模型、独立观测。这是质量稳定性的关键，也是"AI 放大判断力而非替代判断力"的工程落地。

关键工程治理：所有动态配置走 ConfigKey 枚举单一真相源；新能力先上 Feature Flag（默认关闭）→ 人工验证 → 放量；任意功能可通过 ConfigKey 瞬时关闭而无需回滚部署。"上线可观测、可控制、可回滚"。

⑨ 护城河与风险

护城河

  • 质量池是时间复利资产：每次评审都在训练更精准的判断标准
  • 三层垂直整合：单一产品内闭环，竞品难以同时复制
  • 个性化迁移壁垒：工作流越用越适合你
  • 可被 Agent 调用：抢占"智能体时代默认阅读基础设施"的位置

风险与应对

  • 大模型成本飙升 → 多模型分级调用 + 缓存层
  • 内容源封锁 → 多源冗余 + 私有订阅 + 创作者合作
  • 竞品复制策展 → 持续投判断力而非内容量
  • 单人团队瓶颈 → AI 最大化个人产出 + 自动化运营
  • 冷启动流量 → 技术社区精准切入，内容质量即获客

⑩ 如果你要做你自己的产品

下面是从这套产品中提炼的、可直接套用的方法论与决策清单。复刻它的"形"不难，难在复刻它的"魂"——质量判断力。

✅ 该照搬的

  • 拆解式 AI 管线：单一职责节点 + 检查反思 + 优化改进，而非一个巨型提示词
  • 内容状态机：把"质量边界"编码进状态流转，前台只消费终态
  • 公共池 + 个性化层分离：先建公共质量信任，再叠个人工作流
  • ConfigKey + Feature Flag：所有能力可瞬时开关、灰度、回滚
  • 反指标：明确"拒绝优化什么"（时长/数量/无深度日活）

⚠️ 该重新思考的

  • 选垂直领域：他们从技术内容切入。你应选一个你有判断力 / 有信息源优势的窄领域
  • 不要一上来做三层：先把第一层（公共策展）做到让人信任
  • 成本控制前置：LLM 调用是主要成本，从第一天就做缓存 + 多模型分级
  • 人工精审不能省：纯 AI 会让质量天花板封顶，"AI 初筛 + 人工把关"是关键
  • Agent / MCP 接口：这是新增量，可作为你的差异化早期卖点
最关键的一条认知：这个产品的真正资产不是代码，而是"什么是好内容"的判断标准——它沉淀在评分提示词、专家精审规则、标签体系里，随时间复利。你的差异化也应建立在"你比别人更懂哪类内容好"之上。

⑪ MVP 落地路线（单人 / 小团队）

目标：用最小成本验证"个性化高质量策展能否带来留存"。建议技术栈优先简单可演进。

第 1-2 周 · 采集层

跑通"抓取 → 入库"

选 20-50 个你领域内的优质 RSS 源 + 无头浏览器抓全文。存 PostgreSQL/MongoDB。先不做爬虫规模化。

第 3-4 周 · 分析层（核心）

搭 AI 分析管线

用 Dify / LangGraph / 直接调 API 实现：初评过滤 → 摘要+打标+多维评分 → 检查反思。先单语言。把评分提示词当作核心资产反复调。

第 5-6 周 · 分发层

公共内容站 + 每日早报

一个内容列表 + 详情页 + 每天自动生成的"今日精选"邮件/页面。这是你的第一层公共质量池，也是获客入口。

第 7-9 周 · 个性化层

兴趣标签 + 我的早报

新用户冷启动选 5-8 个主题 → 基于标签做"我的早报"。先用规则+标签匹配，不急上向量。

第 10-12 周 · 留存验证

AI 伴读 + 行为埋点

详情页加"总结/提问"。埋点：点击、深读、收藏。观察"深度阅读闭环率"和 7 日留存。

后续 · 商业 & 开放

Pro 订阅 + API/MCP

留存验证通过后再上 Pro（个性化 + 完整伴读）。最后开放 OpenAPI / MCP，吃 Agent 增量。

⑫ 你的差异化切入点（建议）

🎯

更窄的垂直领域

BestBlogs 偏技术泛领域。你可深耕某一窄领域（如某行业/某语言/某职能），用"更懂"换"更准"。

🗣️

本地化 / 单语言

聚焦中文创作者生态 / 某语种，省掉双语翻译成本，把预算投在判断力上。

🤖

Agent-first

直接以 MCP / Agent Skills 为第一形态，做"给 Agent 用的策展 API"，避开前端站点的运营重担。

📥

个人知识库导向

更重"沉淀"（第二阶段方向），做 Readwise + 策展的结合，主打回顾与复用。

👥

社区化策展

引入人工众包精审 + 投票，用社区信号替代/补充昂贵的专家精审。

💰

更低成本模型策略

用小模型做初评 + 大模型做精分析，把单篇分析成本压到可规模化的水平。

一句话总结复刻策略：照搬"公共质量池 + 个性化工作流 + 拆解式 AI 管线"这套骨架，但在"领域选择 + 判断标准 + 成本结构 + 分发形态"上做出属于你自己的选择。骨架是共通的，灵魂必须是你自己的。
