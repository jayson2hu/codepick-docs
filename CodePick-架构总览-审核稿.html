1产品语境

🎯

是什么

面向全球开发者的 AI Coding 高质量阅读工作流：每天替你判断"值得读什么"，生成个性化早报，并让人和 AI Agent 都能调用这份判断。

👤

给谁

用 AI 写代码 / 做 Agent 的开发者；Claude Code / Cursor 重度用户；需要中英内容的技术人群。

💡

核心价值

"Read less, but the right things." 判断前置——AI 判断值不值得读，而非只做"读得快"。

两个产品，一个平台：产品一 Reader（人用的 Web 阅读工作流）与产品二 Agent API/MCP（机器用的策展接口），共享同一个分层数据平台。架构的全部张力，就在于哪些共享、哪些分开。

一句话读懂：数据自下而上被「提纯 → 加工 → 判断 → 消费」。下层稳定通用、被复用；上层易变垂直、可拆分。L0/L1 共享一份（省成本 + 支撑跨垂直综合），L2/L3 按垂直与产品分开（差异化与护城河）。

3架构原则

①

分层单向依赖

上层依赖下层，下层绝不反向。L0 不知垂直，L1 不知产品。

②

数据唯一真相源

内容全局唯一；基础分析算一次；垂直评分按 content×vertical 派生。

③

判断与数据分离

L0/L1 无业务判断；判断集中 L2，可调可审可回溯。

④

先单体后拆分

MVP 单仓多模块 + 单机；按真实瓶颈再拆，不过早复杂化。

⑤

成本即一等约束

LLM 分级 + 缓存 + 只深分析高价值内容，贯穿 L1/L2。

⑥

跨站预留，先穿一站

平台按多垂直抽象，业务先把 AI Coding 一站做穿。

6数据架构

🐘

PostgreSQL

主存储/真相源：实体、分析、评分、用户、订阅

🧲

pgvector

内容/兴趣 embedding，kNN 语义召回

⚡

Redis

缓存 · 队列 broker · 限流/配额计数

🪣

对象存储

原文 HTML · 早报音频（S3/R2）

核心表（跨层）

-- L0 数据底座
sources(id, name, feed_url, type, crawl_config jsonb, is_public, owner_user_id?, vertical_codes[])
content_items(id, canonical_url, url_hash UNIQUE, simhash, title, lang, source_id,
              raw_ref, clean_text_ref, published_at, fetched_at,
              status [WAIT_FILTER|WAIT_ANALYSIS|WAIT_SCORE|WAIT_REVIEW|COMPLETED|CANCELLED])

-- L1 加工（算一次，全局复用）
content_base_analysis(content_id PK FK, one_liner, summary, key_points jsonb, quotes jsonb,
              entities jsonb, base_tags jsonb, embedding vector(1536), model, created_at)

-- L2 判断（content × vertical，每垂直一份）
verticals(code PK, name, rubric_prompt, tag_taxonomy jsonb, source_filter jsonb, enabled)
content_vertical_scores(content_id, vertical_code, relevance,
              dim_scores jsonb {topic,content,depth,practical,novelty,expression},
              vertical_tags jsonb, quality_score, reviewed, PK(content_id, vertical_code))
content_translations(content_id, lang, fields jsonb)

-- L3 产品（每产品/站）
users · subscriptions · user_interests · user_follows · reading_events ·
briefs · bookmarks · api_keys · api_usage_daily
内容状态机即质量边界：WAIT_FILTER → WAIT_ANALYSIS → WAIT_SCORE → WAIT_REVIEW → COMPLETED。L3 仅消费 COMPLETED，未完成态不得进入任何公共/对外结果。

7AI / Agent 架构（LangGraph）

AI 能力以独立的 LangGraph 图实现，可单独调试、换模型、观测、重试。模型分级：便宜模型初评，中端模型分析/评分。

① 基础分析图 (L1, 与垂直无关)
filter(cheap LLM, 低质→CANCELLED) ─▶ branch by length
   ├ short ─▶ analyze_full ─┐
   └ long  ─▶ split ▶ map(analyze_chunk) ▶ aggregate ─┤
        ─▶ extract(one_liner,summary,key_points,quotes,entities) ▶ embed ▶ base_tag ▶ persist

② 垂直评分图 (L2, 注入 rubric)
relevance_gate ─▶ score_6dim(rubric注入) ─▶ vertical_tag
   ─▶ reflect/check(领域评审专家) ─▶ refine ─▶ persist ─▶ review_queue?

③ 翻译图 (L2, 中英双向)
identify_terms ─▶ translate ─▶ check ─▶ refine(意译) ─▶ persist

④ 伴读图 (L2, 请求时 SSE)
load(base_analysis+text) ─▶ retrieve(相关段落) ─▶ answer(流式) ─▶ log(quota)
🎚️

模型分级

filter=小模型；analyze/score=中端；按 ConfigKey 切换

💾

缓存/幂等

按 content+graph 版本缓存；节点可重试，失败不阻塞发布

🔭

可观测

LangSmith/自建 trace；每节点输入输出留痕便于调 prompt

8API 与集成

面前缀鉴权消费者
用户 API / BFF/api/*Session / JWTReader Web（内部）
对外开放 API/v1/*X-API-KEY + 限流 + 配额开发者 / Agent / 第三方
MCP—API Key（env）Claude / Cursor / 自建 Agent

对外原语（只读）：/v1/today · /v1/search · /v1/items/:id · /v1/trending · /v1/sources · /v1/verticals。

信任边界隔离：内部 /api 与对外 /v1 走不同前缀、不同过滤器、不同鉴权，避免"同前缀不同信任边界"误伤。对外只暴露稳定原语，不透出推荐决策与隐私上下文。

11关键数据流（时序）

内容生产（L0 → L3 发布）

L0 源轮询发现新 URL → Playwright 抓全文 → 提取正文 → 去重 → 建 ContentItem(WAIT_FILTER)
L1 初评过滤（小模型，低质→CANCELLED）→ 基础分析 → embedding → 写 base_analysis
L2 对匹配垂直算六维分+标签 → 翻译图产中英 → 写 vertical_scores/translations
L2 低置信/高曝光进精审 → 通过 → status=COMPLETED
L3 进入公共精选 / 早报候选 / 对外 API 可见

我的早报 (Cron)

取兴趣→召回(标签+向量)→去重→重排(质量×权重+新鲜度−多样性)→渲染→邮件

/v1 请求

Key校验→限流→配额→查 COMPLETED+vertical_scores→裁剪字段→返回(含 quota)

MCP 调用

Agent 触发 tool→mcp-server 用 env key 调 /v1→结构化 JSON 回 LLM

16演进路线 + 架构决策 (ADR)

阶段架构形态触发信号
MVP单仓多模块；api+worker 两进程；单机 compose验证判断力与 MVP 闭环
V1worker 按层拆进程；托管 PG；CDN；缓存完善有留存与付费信号
V2public-api/mcp 独立扩展；ES 搜索读模型；向量召回增强API/Agent 调用上量
跨站新增 L2 lens + L3 站；跨垂直综合服务第一站 PMF 后
ADR-1分层数据平台（L0–L3）而非单体业务应用
支持多垂直/跨站复用与判断/数据分离；代价是早期抽象成本，用"先穿一站"对冲。
ADR-2后端 Python，AI 编排 LangGraph
AI/Agent 生态原生在 Python；LangGraph 提供图式编排/状态/分支/重试/可观测，契合多 Agent 分层。前端仍 Next.js（SEO+i18n）。
ADR-3PostgreSQL + pgvector 作单一主存储
关系+jsonb+向量一体化，少组件、运维简单；规模化后再引入 ES 作搜索读模型。
ADR-4基础分析算一次(L1)，垂直评分按 content×vertical 派生(L2)
内容唯一、成本只付一次；垂直价值各算一份。这是成本优势与跨垂直综合能力的来源。
ADR-5先单体多模块 + 单机，按瓶颈再拆
单人/小团队优先开发速度与低运维；代码已按层划分，拆分成本低。
ADR-6对外 API 只暴露稳定原语，信任边界隔离
