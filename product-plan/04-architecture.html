架构总览

InsightFlow 采用"前后端分离 + 微服务 + 事件驱动"的架构，核心分为五层：客户端层、接入层、业务服务层、AI 与数据层、基础设施层。

关键链路一：内容采集与评分

这是 InsightFlow 最核心的数据流。每天处理 10 万+ 篇新文章，目标延迟 < 30 分钟。

1
源轮询 (Crawler)
按订阅源 TTL 拉取 RSS / 公众号 / Twitter / YouTube，去重写入 Kafka raw_articles topic
2
正文抽取 (Extractor)
Readability + 自研规则，去广告 / 去样板代码，输出干净的 Markdown
3
语言检测 + 翻译
非中文内容触发翻译服务（GPT-5 + 术语库），中英双语并存
4
向量化 (Embedding)
用 bge-m3 生成段落级嵌入，写入 Qdrant，用于后续检索与去重
5
AI 多维评分
Claude Haiku 进行五维评分（原创度/密度/深度/时效/作者），输出 0-100 分
6
摘要预生成
对 ≥ 80 分文章预生成 3 档摘要（100/300/500 字）并缓存，降低用户侧延迟
7
入库 + 索引
写入 PostgreSQL（结构化）+ ES（全文检索）+ Qdrant（语义检索）
8
推荐分发
触发推荐计算，更新用户首页信息流，发送个性化推送

关键链路二：AI 阅读助手 (RAG)

用户对一篇文章追问"这个观点和我之前读过的有什么不同？"——这需要跨文献检索 + 上下文推理。

# 伪代码：追问对话的 RAG 流程 def answer_with_context(user_id, article_id, question): # 1. 提取当前文章上下文 article = db.get_article(article_id) # 2. 在用户的阅读历史中检索相关段落 user_history_vec = embed(question) related = qdrant.search( collection=f"user_{user_id}_reads", vector=user_history_vec, limit=5, filter={"read_at__gte": now() - days(90)} ) # 3. 构造 prompt，注入跨文献证据 context = build_context(article, related) # 4. 调用 LLM 流式输出 return claude.stream( model="claude-opus-4-7", system=READING_ASSISTANT_PROMPT, messages=[{"role": "user", "content": question}], context=context, cache_control={"type": "ephemeral"} # 复用 prompt cache )
性能关键：用 Claude 的 prompt caching 缓存文章正文与系统提示（命中率 ≥ 70%），单次追问成本降至 $0.002 以下。
