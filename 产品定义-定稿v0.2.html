码间精选 / CodePick —— 产品定义（定稿 v0.2）

面向全球开发者的 AI Coding 高质量阅读工作流，构建在一个分层数据平台之上：最底层提供统一数据支撑，上层逐级加工、判断、智能体化，最终支撑多个产品与站点（可跨站复用）。本稿已并入你确认的全部决策，作为规划开发 Plan 的基准。

★分层数据平台（核心架构）

按你的要求：最底层提供数据支撑，上层对数据加工、拆分、或运行各种智能体；整体可拆分为若干分层，后续支持跨站。自下而上四层：

消费层
LAYER 3 · PRODUCTS & SITES
产品与站点层 （可跨站 / 多产品复用下层）
AI Coding Reader 站 · 未来其他垂直站 · Agent API + MCP · Newsletter · 嵌入式组件。各产品/站点只做"消费 + 体验 + 商业化"，全部复用 L0–L2。
▲ 调用下层能力 · 回流行为数据 ▼
智能层
LAYER 2 · JUDGMENT & AGENTS
判断与智能体层 （按垂直 / 场景拆分）
垂直评分 Agent（content×vertical 六维分）· 精审 · 翻译 Agent（中英）· 推荐/重排 · 伴读问答 · 研究/监控 Agent。护城河在此层，由 LangGraph 编排。
▲ 读取结构化内容 ▼
共享
LAYER 1 · ENRICHMENT
数据加工层 （与垂直无关，算一次，全局复用）
清洗/规范化 · 基础分析（一句话/摘要/关键观点/金句/实体）· embedding · 基础打标 · 语言识别。把原始数据加工成"结构化内容知识"。
▲ 读取干净原始数据 ▼
共享
LAYER 0 · DATA FOUNDATION
数据底座 （最底层 · 纯数据支撑 · 不含业务判断）
采集（RSS + 无头浏览器全文）· 内容实体 ContentItem（全局唯一、去重）· 源注册表 · 原文/对象存储 · 统一可信的数据真相源。PostgreSQL + pgvector。
分层原则：下层稳定、通用、可复用；上层易变、垂直、可拆分。L0/L1 共享（成本只付一次，也是跨站综合能力的来源），L2/L3 按垂直与产品分开（差异化与护城河）。新增一个垂直 = 配置一个 L2 lens + 新建一个 L3 站点，L0/L1 不动。

  • 跨站复用：每个垂直站点（L3）共享同一套 L0/L1；只需新增 L2 的垂直 lens（源过滤 + 评分 rubric + 标签体系）。
  • 跨站综合：因数据底座唯一，可做单垂直玩家做不到的跨垂直主题/交叉分析（如 AI×DevOps）。
  • 统一 Agent 接口：产品二（API/MCP）天然是"跨站"的——一个接口可按 vertical 参数服务所有垂直站。
落地纪律：平台能力（L0–L2）从第一天就按"多垂直/多站点"抽象；但业务先做穿 AI Coding 一个站，验证 PMF 后再开第二站。架构预留 ≠ 一次性全建。

⛬数据归属与边界

数据归属说明
ContentItem（内容实体）L0 全局唯一一篇 = 一条；按 url_hash + simhash 去重
BaseAnalysis（基础分析）L1 算一次摘要/观点/金句/实体/embedding，与垂直无关
VerticalScore（垂直评分）L2 每垂直一份content × vertical 多对多；同一篇在不同站分数不同
用户/行为/订阅L3 每产品/站账户、兴趣、行为、Pro 订阅；隐私上下文不外泄

2用户与问题

目标用户（全球）

  • 核心：全球用 AI 写代码 / 构建 Agent 的开发者、独立开发者、技术 leader
  • 重度：Claude Code / Cursor / Copilot 用户（天然对接产品二 MCP）
  • 双语：英文母语者 + 需要中英内容的华语开发者

解决的问题

  • 发现与判断：AI Coding 日更爆炸，判断成本高于获取成本
  • 吸收效率：长文/多语种太多，需先压缩+排序
  • 沉淀缺失：读过即忘，缺持续跟踪

5差异化与护城河

差异化

  • 只做 AI Coding，比泛技术策展更懂黑话与价值
  • Agent-first：MCP/API 一等公民（跨站统一接口）
  • 判断前置（值不值得读），非只做"读得快"
  • 分层平台 → 低边际成本扩垂直 + 跨垂直综合

护城河（复利）

  • 领域评分 rubric + 标签体系（L2，抄不走）
  • 你本人的领域信誉
  • 个性化迁移壁垒（越用越准）
  • 统一数据底座 + Agent 生态卡位

10风险与红线

风险应对
LLM 成本小模型初评 + 缓存 + 只对高价值内容深分析；LangGraph 分级调用
内容源/版权（跨境）只存摘要+分析+链接（不全文转载），标注来源，多源冗余
海外合规/税务Paddle 作 MoR 处理全球税；隐私（GDPR）合规设计
通用 AI 替代护城河是持续判断标准 + 追踪 + 源质量，非单次摘要
单人断档自动化 + 精审流程化；分层平台降低维护面
红线：不以时长为目标、不做泛化 AI 工具箱、不以内容数量取胜。价值 = 帮用户读得更少但更对。
