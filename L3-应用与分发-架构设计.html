L3 应用与分发 — 架构设计

面向终端的服务层：Reader Web（Next.js）+ reader-api/public-api（FastAPI）+ mcp-server + briefs-worker。只消费下层 COMPLETED 产物，聚焦体验、分发、计费，并严格隔离内部与对外信任边界。

1设计目标

⚡

秒开体验

详情直接读 L1/L2 产物，不在请求路径调 LLM（伴读除外）。

🔐

边界隔离

内部 /api 与对外 /v1 分前缀/过滤器/鉴权。

🌍

SEO + i18n

SSR 利于获客；中英双语。

💳

USD 计费

Paddle/Stripe；门禁集中治理。

↔️

可跨站

站点是 L3 实例，复用同平台。

📊

可度量

北极星埋点贯穿。

4鉴权边界（关键）

面前缀鉴权消费者
内部用户 API/api/*Session/JWTReader Web
对外开放 API/v1/*X-API-KEY+限流+配额开发者/Agent
MCP—API Key(env)Claude/Cursor

不同信任边界物理隔离：内部 /api 与对外 /v1 走不同服务/过滤器；对外只暴露稳定原语，不透出推荐决策与隐私上下文。门禁(Free/Pro)集中在服务层治理，不散落前端。

6早报生成（Cron）

公共早报：取近 3 天 COMPLETED + 高 quality_score，加权(来源/类型)+历史去重 → 渲染
我的早报：遍历 Pro 用户，取兴趣 → 召回(标签+向量，调 L2)→ 去重 → 重排 → topN
渲染中英双语 → 写 briefs → 邮件投递（Resend/SES）→ 可选音频
记录投递与打开，回流北极星指标

7AI 伴读与计费

  • 伴读：reader-api 收到提问 → 检查 companion_usage 配额（Free 限量/Pro 全量）→ 调 L2 伴读图 → SSE 流式返回 → 计数。
  • 计费：Paddle/Stripe Checkout → /webhooks 验签 → 更新 subscriptions/plan → 门禁实时生效。
  • 门禁：统一 require_plan() 中间件，集中治理，避免规则漂移。

9技术选型

前端Next.js (App Router) + TS + Tailwind，SSR/SEO/i18n
用户 APIPython FastAPI（reader-api），JWT
对外 APIFastAPI（public-api），API Key + Redis 限流/配额
MCPMCP Python SDK（mcp-server）
早报Arq/Celery cron（briefs-worker）+ Resend/SES
支付Paddle（MoR，省全球税）/ Stripe（USD）

10部署

MVP：reader-web + api（合并 reader-api/public-api）+ worker(含 briefs)。规模化：public-api/mcp 独立扩展；reader-web 上 CDN；按对外流量与内部流量隔离。

11风险

风险应对
信任边界混淆内部/对外分服务、分前缀、分过滤器
配额/限流绕过Redis 共享计数；服务端强制
跨境支付/税务Paddle 作 MoR；GDPR 合规
SEO 与 i18n 复杂度SSR + hreflang + 结构化数据
全平台闭环：L0 采集→L1 加工→L2 判断→L3 分发，四层各为独立产品、共享一份数据、最终在 L3 兑现价值。整体见《CodePick 架构总览》。
