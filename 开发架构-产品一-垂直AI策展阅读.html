产品一：垂直 AI 策展阅读（Reader）

面向 C 端读者的 Web 产品：在一个垂直领域内，把"今天值得读什么"判断好，生成个性化早报，并提供 AI 伴读。本文档描述其完整开发架构——采集与基础分析复用共享内容中台，本产品聚焦垂直判断、个性化、分发与账户/订阅。

定位与边界

🎯

它负责

垂直评分与精审、兴趣标签与行为学习、我的早报、为你推荐、AI 伴读、Web/邮件分发、账户与订阅

🔗

它复用

共享中台的：采集、内容实体、基础分析（摘要/观点/金句/实体/embedding）

🚫

它不做

对外开放 API / MCP（那是产品二）；不重复爬取、不重复基础分析

共享原则（与上一轮讨论一致）：一条内容全局唯一，基础分析算一次；"它对某垂直的价值（评分/标签）"是 content × vertical 的每垂直一份记录。本产品消费 COMPLETED + 已精审 的垂直评分结果。

人/系统角色：读者（免费/Pro）、内容源（外部）、LLM 提供方、支付。Reader 本身不直接爬取——它消费中台产出。

② 共享内容中台（边界）

两个产品共用。这里只描述边界与职责；实现细节在中台自身仓库/模块维护。Reader 以"只读已发布内容 + 读写垂直评分"的方式接入。

共享
采集层 · Ingestion
源注册表 + RSS 轮询 + 无头浏览器全文抓取（Playwright）+ 正文提取/清洗。通用源共享；垂直私有源由本产品追加。
共享
内容实体层 · ContentItem
规范化记录，按 url_hash + simhash 全局去重。一篇 = 一条。原文 HTML/正文存对象存储，元数据入库。
共享
基础分析层 · BaseAnalysis
LLM 算一次：一句话总结、摘要、关键观点、金句、实体、基础标签、embedding。与垂直无关的"事实层"。
本产品
垂直判断层 · VerticalScore
按 content × vertical 算：相关性 + 六维分 + 垂直标签 + 精审状态。护城河在这层，每垂直独立 rubric。
接入方式：中台完成基础分析后，发事件 content.analyzed；Reader 的"垂直评分 Worker"订阅该事件，对匹配本产品垂直的内容计算 VerticalScore，写回共享库 → 进入精审队列 → COMPLETED。

④ 核心模块 (C4 Level 3)

模块职责关键点归属
垂直评分 Worker订阅 content.analyzed，对匹配垂直算相关性+六维分+垂直标签输入用 BaseAnalysis（不重读全文），轻量便宜；写 VerticalScore本产品
精审队列低置信/高曝光内容进人工/半自动复审阈值由 ConfigKey 控；通过→COMPLETED本产品
个性化召回重排为你推荐 / 我的早报候选集多路召回(标签+向量)→重排：qualityScore×标签权重+新鲜度−多样性惩罚本产品
AI 伴读 Service详情页总结/问答/章节跳转，SSE 流式注入内容上下文；配额按 Free/Pro；用量计数本产品
早报生成 Job公共早报(底稿) + 我的早报(逐用户)Cron；3 天窗口+历史去重+质量检查；产文字/音频/邮件本产品
行为采集点击/深读/收藏/划线/不感兴趣异步写入；喂回兴趣权重与来源偏好本产品
账户/订阅登录、Free/Pro 门禁、计费门禁集中治理；Stripe/国内支付 webhook本产品
BFF面向 Web 的聚合接口、鉴权、SSE唯一前端调用入口；不泄漏内部规则本产品

⑤ 数据模型

共享层（中台 + 垂直评分）

table sources            -- 订阅源（含垂直私有源）
  id, name, feed_url, type[article|podcast|video|tweet],
  crawl_config jsonb, is_public bool, owner_user_id?, vertical_codes text[]

table content_items       -- ★ 全局唯一、去重
  id, canonical_url, url_hash unique, simhash, title, lang,
  source_id, raw_ref(对象存储), clean_text_ref, published_at, fetched_at,
  status[WAIT_FILTER|WAIT_ANALYSIS|WAIT_REVIEW|COMPLETED|CANCELLED]

table content_base_analysis  -- 共享，算一次
  content_id pk fk, one_liner, summary, key_points jsonb, quotes jsonb,
  entities jsonb, base_tags jsonb, embedding vector(1536), model, created_at

table content_vertical_scores -- ★ content × vertical，每垂直一份（判断层）
  content_id fk, vertical_code fk, relevance int,
  dim_scores jsonb{选题,内容,深度,实用,创新,表达}, vertical_tags jsonb,
  reviewed bool, review_note, quality_score int,
  primary key (content_id, vertical_code)

table verticals             -- lens 配置（一行 = 一个垂直）
  code pk, name, rubric_prompt, tag_taxonomy jsonb,
  source_filter jsonb, brief_template, enabled bool

本产品独有（账户 / 个性化 / 分发）

table users               id, email, nickname, created_at, plan[free|pro]
table subscriptions       user_id, plan, status, period_end, provider, provider_ref
table user_interests      user_id, tag_code, weight -- 可跨垂直
table user_follows        user_id, target_type[source|vertical], target_id
table reading_events      user_id, content_id, type, ts -- 行为，喂回权重
table briefs              id, user_id?(null=公共), vertical_code, brief_date,
                       items jsonb, audio_ref?, channels jsonb, status
table bookmarks           user_id, content_id, note, highlights jsonb
table companion_usage     user_id, day, count -- AI 伴读配额计数

降本关键：① 小模型初评砍掉 60-70% 低质再进大模型；② 垂直评分只吃 BaseAnalysis（不重读全文），新增垂直边际成本极低；③ 命中缓存复用。

B. 我的早报生成（Cron 07:00）

遍历活跃用户，取其关注垂直/兴趣标签
从 COMPLETED 内容召回候选（近 3 天，标签通道 + 向量通道并行）
对照该用户历史早报去重，避免重复推荐
重排：qualityScore × 标签权重 + 新鲜度 − 多样性惩罚，取 Top N
渲染早报（文字）→ 可选生成音频 → 写 briefs → 邮件投递

C. AI 伴读（详情页，SSE 流式）

用户打开 /read/{id}，BFF 立即返回 BaseAnalysis（秒开，无需调用 LLM）
用户提问 → BFF 检查配额（Free/Pro）→ 注入内容上下文，SSE 流式调用 LLM
回写 companion_usage 计数；记录 reading_event(type=deepread)

⑦ 技术选型

层选型理由 / 备选
前端 / SSRNext.js (App Router) + TypeScript + TailwindSSR 利于 SEO（获客核心）；备选 Remix
BFF / APINext API Routes / Hono早期同仓即可；规模化拆 NestJS
Worker / JobNode + BullMQ（Redis 队列）定时与异步管线；备选 Temporal
主存储PostgreSQL + Prisma关系+jsonb 够用，运维简单；BestBlogs 用 Mongo 亦可
向量pgvector（起步）→ Qdrant少一个组件，够用即止
缓存/队列/限流Redis三用合一
对象存储S3 兼容（R2/MinIO）存原文 HTML、早报音频
LLM 编排Dify 自部署 或 直连 SDK + 轻编排Dify 可视化调 prompt（BestBlogs 同款）；追求轻量则直连
邮件 / 音频Resend / SES · TTS（火山/Azure/OpenAI）早报分发
支付Stripe（海外）/ 微信支付·支付宝（国内）订阅计费

⑨ 部署拓扑（分阶段）

①

MVP（单 VPS）

docker-compose：web+bff+worker 同栈，postgres、redis、playwright。Dify 可选单容器。月成本 $60-300。

②

成长期

拆 Worker/Job 独立进程；托管 Postgres；Web 上 CDN；对象存储独立。

③

规模化

多实例 Web 水平扩展；任务锁去重；Redis 集群；ES 作搜索读模型。

⑩ 横切机制

配置与门禁

  • ConfigKey 单一真相源：开关/阈值/配额禁止硬编码
  • Free/Pro 门禁集中治理，不散落到各入口
  • 新能力先 Feature Flag（默认关）→ 验证 → 放量

缓存 / 可观测

  • 本地缓存 + Redis + 数据源三层
  • 关键路径有日志/计数/告警（可回滚）
  • 北极星埋点：深度阅读闭环率，非时长/DAU

⑪ 开发里程碑（依赖顺序）

M1 · 中台地基

采集 + 内容实体 + 基础分析

跑通"抓取→去重→初评→基础分析→入库"。先单垂直、单语言。

M2 · 判断层

垂直评分 Worker + 精审

把人工评分标准翻译成 rubric prompt；产出 COMPLETED 内容。

M3 · 公共站 + 早报

内容广场 + 自动早报

Next.js 列表/详情 + Cron 公共早报（邮件/页面）。SEO 友好。

M4 · 个性化 + 伴读

我的早报 + AI 伴读 + 行为

兴趣标签、召回重排、SSE 伴读、行为埋点；盯留存。

M5 · 商业化

账户 + Pro 订阅

门禁、计费、配额；主推年费。验证单位经济。
