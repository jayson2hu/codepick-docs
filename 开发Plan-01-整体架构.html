开发 Plan · 文档 01 / 整体架构

CodePick — 分层数据平台 · 整体架构

本文档从逻辑、服务、数据、AI/Agent、API、部署、横切、质量属性、跨站可扩展、架构决策等多个视角，解析 CodePick（AI Coding 高质量策展，面向海外、中英双语）的整体架构。它是后续模块级开发 Plan 的总纲与约束基准。

产品：CodePick / 码间精选 后端：Python · FastAPI · LangGraph 前端：Next.js 存储：PostgreSQL + pgvector · Redis 形态：分层平台 + 跨站

i文档说明

这是"整体架构"——给出跨视角的全貌与边界约束，不下沉到逐文件实现。后续 Plan 将按本文档拆出：数据库 DDL、LangGraph 管线/Agent prompt、模块代码骨架、周级任务与排期、成本模型、验收标准。

解析采用类 arc42 / 4+1 视图的方式：逻辑视图（分层）、开发视图（仓库）、进程视图（服务/数据流）、物理视图（部署）、以及贯穿其中的场景与质量属性。

一句话读懂：自下而上，数据被逐层"提纯—加工—判断—消费"。下层稳定通用、被复用；上层易变垂直、可拆分。L0/L1 共享一份（省成本、能跨垂直综合），L2/L3 按垂直与产品分开（差异化与护城河）。

2架构原则

①

分层单向依赖

上层依赖下层，下层绝不反向依赖上层。L0 不知道垂直，L1 不知道产品。

②

数据唯一真相源

一篇内容全局唯一；基础分析算一次；垂直评分按 content×vertical 派生。

③

判断与数据分离

L0/L1 不含业务判断；判断集中在 L2，可调可审可回溯。

④

先单体后拆分

MVP 单仓多模块 + 单机部署；按真实瓶颈再拆服务，不过早复杂化。

⑤

成本即一等约束

LLM 分级调用 + 缓存 + 只深分析高价值内容，贯穿 L1/L2。

⑥

跨站预留，业务先穿一站

平台能力按多垂直抽象，但先把 AI Coding 一站做穿。

3逻辑架构（L0–L3 详解）

L3
PRODUCTS & SITES
产品与站点层
组件：Reader Web（公共精选/我的早报/推荐/AI伴读/账户）· Public API /v1 · MCP Server · Brief/Newsletter。职责：体验、分发、商业化；只消费下层，不重算。
L2
JUDGMENT & AGENTS
判断与智能体层
组件：垂直评分 Agent（六维分+相关性+垂直标签）· 翻译 Agent（中英）· 推荐/重排 · 伴读 QA · 研究/监控（后期）。职责：在结构化内容上做判断与智能处理，按垂直 lens 与场景拆分；LangGraph 编排。
L1
ENRICHMENT
数据加工层
组件：清洗/规范化 · 初评过滤 · 基础分析（一句话/摘要/关键观点/金句/实体）· embedding · 基础打标 · 语言识别。职责：把原始数据加工为"结构化内容知识"，与垂直无关、算一次。
L0
DATA FOUNDATION
数据底座
组件：源注册表 · RSS 轮询 · Playwright 全文抓取 · 正文提取 · 去重（url_hash+simhash）· ContentItem 实体 · 原文对象存储。职责：提供干净、统一、可信的数据真相源；无业务判断。
层输入输出关键表/产物共享性
L0外部源规范化内容实体sources, content_items, 对象存储全局共享
L1content_items结构化内容知识content_base_analysis (+embedding)全局共享·算一次
L2base_analysis垂直判断 + 翻译content_vertical_scores, translations每垂直一份
L3COMPLETED 内容体验 + 分发 + 计费users, briefs, api_keys ...每产品/站

5数据架构

存储职责

🐘

PostgreSQL

主存储与真相源：实体、分析、评分、用户、订阅

🧲

pgvector

内容/用户兴趣 embedding，kNN 语义召回

⚡

Redis

缓存、队列 broker、限流/配额计数

🪣

对象存储

原文 HTML、早报音频（S3/R2）

核心表（跨层）

-- L0 数据底座
sources(id, name, feed_url, type, crawl_config jsonb, is_public, owner_user_id?, vertical_codes[])
content_items(id, canonical_url, url_hash UNIQUE, simhash, title, lang,
              source_id, raw_ref, clean_text_ref, published_at, fetched_at,
              status [WAIT_FILTER|WAIT_ANALYSIS|WAIT_SCORE|WAIT_REVIEW|COMPLETED|CANCELLED])

-- L1 加工（算一次，全局复用）
content_base_analysis(content_id PK FK, one_liner, summary, key_points jsonb,
              quotes jsonb, entities jsonb, base_tags jsonb,
              embedding vector(1536), model, created_at)

-- L2 判断（content × vertical，每垂直一份）
verticals(code PK, name, rubric_prompt, tag_taxonomy jsonb, source_filter jsonb, enabled)
content_vertical_scores(content_id, vertical_code, relevance,
              dim_scores jsonb {topic,content,depth,practical,novelty,expression},
              vertical_tags jsonb, quality_score, reviewed, PK(content_id, vertical_code))
content_translations(content_id, lang, fields jsonb {summary,key_points,quotes,...})

-- L3 产品（每产品/站）
users, subscriptions, user_interests, user_follows, reading_events,
briefs, bookmarks, api_keys, api_usage_daily
内容状态机即质量边界：WAIT_FILTER → WAIT_ANALYSIS → WAIT_SCORE → WAIT_REVIEW → COMPLETED。L3 仅消费 COMPLETED，未完成态不得进入任何公共/对外结果。

6AI / Agent 架构（LangGraph）

AI 能力以 LangGraph 图（StateGraph）实现，按职责拆成独立图，可单独调试、换模型、观测、重试。模型分级：便宜模型做初评，中端模型做分析/评分。

① 基础分析图（L1，与垂直无关）

enrichment_graph:
  filter (cheap LLM: 剔低质/营销, ignore→CANCELLED)
    └▶ branch by length
         ├ short ─▶ analyze_full
         └ long  ─▶ split ▶ map(analyze_chunk) ▶ aggregate
              └▶ extract (one_liner, summary, key_points, quotes, entities)
                   └▶ embed (→ pgvector) ▶ base_tag ▶ persist

② 垂直评分图（L2，注入垂直 rubric）

scoring_graph(vertical):
  relevance_gate (是否属于该垂直? 否→跳过)
    └▶ score_6dim (rubric_prompt 注入: topic/content/depth/practical/novelty/expression)
         └▶ vertical_tag (垂直标签体系)
              └▶ reflect/check (扮演领域评审专家，查全面/准确/一致)
                   └▶ refine ▶ persist(content_vertical_scores) ▶ review_queue?

③ 翻译图（L2，中英双向）

translate_graph(target_lang):
  identify_terms ▶ translate ▶ check ▶ refine(意译) ▶ persist(content_translations)

④ 伴读 / 研究（L2，请求时）

companion_graph: load(base_analysis+text) ▶ retrieve(相关段落) ▶ answer(SSE 流式) ▶ log(quota)
🎚️

模型分级

filter=小模型；analyze/score=中端；可按 ConfigKey 切换

💾

缓存与幂等

按 content+graph 版本缓存；节点可重试，失败不阻塞发布链路

🔭

可观测

LangSmith/自建 trace；每节点输入输出留痕，便于调 prompt

7API 与集成架构

面前缀鉴权消费者
用户 API / BFF/api/*Session / JWTReader Web（内部）
对外开放 API/v1/*X-API-KEY + 限流 + 配额开发者 / Agent / 第三方

信任边界隔离：内部 /api 与对外 /v1 走不同前缀、不同过滤器、不同鉴权，避免"同前缀不同信任边界"误伤。对外只暴露稳定原语（today/search/analyze/trending/sources），不透出推荐决策与隐私上下文。

8部署与基础设施

①

MVP（单 VPS）

docker-compose：reader-web · api · worker · postgres(pgvector) · redis · playwright。月成本 $60–300。

②

成长期

拆 worker（ingest/enrich/score/brief）独立进程；托管 Postgres；Web 上 CDN；对象存储独立。

③

规模化

API 多实例水平扩展；任务锁去重；Redis 集群；可选 ES 作搜索读模型。

11关键数据流（时序）

A. 内容生产（L0→L3 发布）

L0 源轮询发现新 URL → Playwright 抓全文 → 提取正文 → 去重 → 建 ContentItem(WAIT_FILTER)
L1 enrichment 图：初评过滤（小模型，低质→CANCELLED）→ 基础分析 → embedding → 写 base_analysis
L2 scoring 图：对匹配垂直算六维分+标签 → 翻译图产中英 → 写 vertical_scores/translations
L2 低置信/高曝光进精审队列 → 通过 → status=COMPLETED
L3 进入公共精选 / 早报候选 / 对外 API 可见

B. 我的早报（Cron）/ C. 对外 API / D. MCP

B 我的早报

取用户兴趣→召回(标签+向量)→去重→重排(质量×权重+新鲜度−多样性)→渲染→邮件

C /v1 请求

API Key校验→限流→配额→查 COMPLETED+vertical_scores→裁剪字段→返回(含 quota)

D MCP 调用

Agent 触发 tool→mcp-server 用 env key 调 /v1→结构化 JSON 回 LLM

12质量属性（非功能性）

架构对各质量属性的优先级与达成手段（条长表示该架构对此属性的投入强度）。

成本效率
模型分级+缓存+只深分析高价值，最高优先
可扩展性
分层平台+跨站，新增垂直低边际成本
可维护性
代码边界=架构边界；LangGraph 可调可观测
可靠性
状态机+重试+幂等；失败不阻塞发布
性能/延迟
详情秒开(读 base_analysis)；分析走异步
安全/合规
信任边界隔离+GDPR+不全文转载
高可用(HA)
MVP 单机可接受；规模化再做多实例
权衡说明：MVP 阶段刻意牺牲 HA 与极致性能，换取成本、开发速度、可维护性。这符合单人/小团队、内容产品（异步为主、非强实时）的特性。

14架构决策记录 (ADR)

ADR-1采用分层数据平台（L0–L3），而非单体业务应用
理由：支持多垂直/跨站复用与判断/数据分离；代价是早期抽象成本，用"先穿一站"对冲。
ADR-2后端用 Python，AI 编排用 LangGraph
理由：AI/Agent 生态原生在 Python；LangGraph 提供图式编排、状态、条件分支、可观测、重试，契合多 Agent 分层。前端仍 Next.js（SEO+i18n）。
ADR-3PostgreSQL + pgvector 作单一主存储
理由：关系+jsonb+向量一体化，少组件、运维简单、事务清晰；规模化后再引入 ES 作搜索读模型。
ADR-4基础分析算一次（L1），垂直评分按 content×vertical 派生（L2）
理由：内容唯一、成本只付一次；垂直价值各算一份。这是成本优势与跨垂直综合能力的来源。
ADR-5先单体多模块 + 单机部署，按瓶颈再拆
理由：单人/小团队优先开发速度与低运维；避免过早微服务化。代码已按层划分，拆分时低成本。
ADR-6对外 API 只暴露稳定原语，信任边界与内部 API 隔离
理由：受控暴露，保护推荐决策与隐私；前缀/过滤器/鉴权分离避免误伤。
