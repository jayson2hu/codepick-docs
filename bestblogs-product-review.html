BestBlogs.dev 产品理解与仿做架构审阅稿

BestBlogs 的核心不是再做一个 RSS 阅读器，而是用 AI 和人工策展建立公共质量池，再把这套判断力转化为个人阅读工作流，并最终开放给 Agent 和外部系统调用。

三层结构 公共质量池、个人工作流、Agent/API 基础设施
核心资产 内容源、质量判断、结构化分析、用户行为
商业入口 Free 建信任，Pro 承载个性化工作流
MVP 切入 先做垂直领域每日策展，再做推荐和 Agent 化

01 产品本质

BestBlogs 解决的不是“有没有内容”的问题，而是“什么内容值得先看、为什么值得看、是否适合我、看完如何沉淀”的问题。它把内容消费从信息流改造成一个有判断、有压缩、有反馈的阅读工作流。

一句话理解：BestBlogs 是一个 AI 驱动的高质量内容判断系统，而不是简单的信息搬运系统。

用户痛点

  • 每天内容太多，筛选成本高于获取成本。
  • 长内容理解成本高，需要先压缩再深读。
  • 读过的内容难以复用，缺少回顾和沉淀机制。
  • 普通算法推荐不可解释，难以建立长期信任。

产品解法

  • 用公共策展建立质量判断基准。
  • 用 AI 结构化分析降低判断和理解成本。
  • 用用户画像和行为反馈形成个性化推荐。
  • 用 OpenAPI、CLI、Skills 把能力开放给 Agent。

03 三层飞轮

第一层：公共策展质量池

从大量内容中压缩出可信内容集合，是品牌、SEO、获客和信任的来源。

RSS 采集 AI 评分 人工审核 公共早报

第二层：个人阅读工作流

把公共判断力转化为“为我而选”的持续体验，是留存和付费核心。

我的早报 For You AI 伴读 收藏笔记

第三层：可调用基础设施

把内容、判断和上下文开放给外部系统，是 Agent 时代的放大器。

OpenAPI CLI Skills Context Pack

04 内容处理链路

这条链路是产品的生产系统。它把外部原始内容转成可推荐、可阅读、可搜索、可被 Agent 消费的结构化内容资产。

1. 采集RSS、网页、播客、视频、推文
2. 预处理正文提取、清洗、标准化
3. 去重过滤URL、标题、内容 Hash、低质过滤
4. AI 分析评分、摘要、观点、标签、实体
5. 翻译中英双语、术语处理、段落级缓存
6. 人工审核质量确认、修正、发布决策
7. 发布Explore、早报、RSS、搜索、API
8. 反馈点击、阅读、收藏、划线、不感兴趣

内容状态机

WAIT_PREPARE
 → WAIT_FILTER
 → WAIT_ANALYSIS
 → WAIT_TRANSLATE
 → WAIT_REVIEW
 → COMPLETED / CANCELLED

关键约束：只有 COMPLETED + processed=true 的内容才能进入前台、推荐、公共早报和开放接口。

06 推荐原理

BestBlogs 的推荐建立在公共质量池之上，不直接把未审核原始内容推给用户。推荐不是单纯追求点击，而是追求“值得读且适合我”。

最终推荐分 =
  内容质量分
+ 用户兴趣标签匹配
+ 来源偏好
+ 新鲜度
+ 热度
+ 多样性控制
+ 行为反馈权重
- 已读 / 不感兴趣 / 重复内容惩罚

召回路径

  • 兴趣召回：匹配用户选择或学习到的主题。
  • 探索召回：引入用户未关注但高质量的新内容。
  • 热点召回：近期高分高热内容。
  • 协同召回：相似用户也在读的内容。

解释字段

  • candidateSource：来源路径。
  • selectionReason：为什么推荐。
  • fallbackApplied：是否走降级。
  • personalized：是否个性化。

07 AI 分析设计

AI 的作用不是替代判断，而是规模化初筛、结构化分析和辅助理解。真正的产品壁垒来自“稳定的判断标准 + 人工校准 + 长期积累”。

{
  "overallScore": 88,
  "scores": {
    "topic": 9,
    "depth": 8,
    "practical": 7,
    "innovation": 8,
    "expression": 9
  },
  "summary": "文章核心摘要",
  "keyPoints": ["关键观点 1", "关键观点 2"],
  "tags": ["AI Coding", "LLM", "Developer Tools"],
  "entities": ["OpenAI", "Claude Code"],
  "audience": ["software engineer", "product manager"],
  "whyWorthReading": "为什么值得读",
  "qualityRisks": ["可能偏营销", "缺少数据支撑"]
}
做类似产品时，必须要求 AI 输出结构化 JSON，并为 Prompt、模型、分析版本建立版本号。否则后续无法比较、回放和优化。

08 数据模型

内容资产

  • Source：内容源、类型、权重、语言。
  • Resource：文章/播客/视频/推文主体。
  • Analysis：评分、摘要、标签、实体。
  • Brief：公共早报和个人早报。

用户资产

  • UserProfile：兴趣画像和权重。
  • UserBehavior：曝光、点击、阅读、收藏、反馈。
  • Bookmark：收藏。
  • Highlight：划线和笔记。
Source → Resource → Analysis → Review → Publish
                              ↓
UserProfile + UserBehavior → Recommendation → Brief / For You
                              ↓
Capture / Read History → Feedback Loop

09 商业模式

Free 和 Pro 的区别不是“功能多少”，而是价值层级不同。Free 负责证明公共判断力，Pro 负责把判断力变成个人工作流。

版本 价值边界 典型能力
Free 高质量公共输入入口 公共精选、公共早报、基础阅读、基础摘要
Pro 个性化阅读工作流 我的早报、For You、高级 AI 伴读、自定义源、回顾沉淀

10 仿做 MVP

建议不要直接复刻完整 BestBlogs。更稳的路径是先做一个垂直领域版本，例如“AI 工程师每日高质量阅读”。

MVP 保留主链路

RSS 源管理
 → 内容抓取
 → 正文提取
 → 去重
 → AI 评分 / 摘要 / 标签
 → 人工审核
 → 每日精选
 → 用户兴趣设置
 → 个性化早报
 → 阅读 / 收藏 / 反馈

P0 必做

  • 内容源管理
  • 自动抓取与去重
  • AI 结构化分析
  • 人工审核后台
  • 每日精选页面

P1 增强

  • 用户兴趣设置
  • 个人早报
  • For You 推荐
  • 收藏和已读
  • 推荐解释

P2 扩展

  • AI 伴读问答
  • 划线笔记
  • OpenAPI
  • CLI / Agent Skills
  • 主题追踪

11 路线图

阶段 1：公共质量池 100-300 个优质源，每日抓取，AI 初评，人工审核，公开精选。
阶段 2：个人阅读工作流 兴趣设置、个人早报、For You、收藏、已读、不感兴趣。
阶段 3：知识沉淀 划线、笔记、阅读历史、周报、月报、主题回顾。
阶段 4：Agent Native OpenAPI、CLI、MCP/Skills、Context Pack、Research Session。

12 关键风险

风险 表现 应对
内容源质量不足 再好的 AI 也只能压缩低质输入 先做垂直领域，维护高质量源库和源权重
AI 评分不稳定 推荐质量波动，用户不信任 结构化输出、版本管理、人工审核、抽样复评
推荐黑箱化 用户不知道为什么推荐 每条推荐都输出解释字段和反馈入口
过早工程化 系统复杂但产品价值未验证 MVP 阶段推迟消息队列、复杂向量库和独立 worker
成本不可控 LLM 分析、翻译、伴读成本高 分级模型、缓存、批处理、只对候选内容深度分析
最终建议：先证明你能持续选出好内容，再做个性化；先证明个人早报能带来留存，再做 Agent/API 放大。
