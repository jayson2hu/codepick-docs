★关键决策清单（待确认）

这 10 个决策是产品的地基。括号内为我的推荐与理由；请逐条确认或修改。

D1垂直领域选哪个？（最关键）
推荐：AI Coding（AI 辅助编程 / Agent 开发）
理由：① 你是开发者，有判断力（质量池的根）；② 英文源多、中文优质少 → "判断+翻译"价值大；③ 受众是开发者，最易接受 Agent/MCP 形态（直接喂产品二）；④ 信息过载严重、迭代快、付费力强。备选：出海电商 / 量化投资 / 企业 AI 落地。← 此项决定全文示例，请优先确认。
D2先做哪个产品？
推荐：先做产品一 Reader 到留存验证，再低成本上产品二 Agent API
理由：A 建立现金流与判断力地基；B 是 A 的"顺手延伸"（同一份结构化数据加一层读接口），几乎零额外成本，作差异化卡位。详见架构文档。
D3语言策略？
推荐：抓英文源为主 + 中文输出分析结果（翻译摘要/观点/金句，不做全文翻译）
理由：AI Coding 一手内容多为英文；只翻译"分析结果"而非全文，成本低、价值高，正中"帮中文开发者省时间"。后续再考虑沉浸式全文翻译（Pro）。
D4定价模型？
推荐：Free + Pro；Pro 主推年费 ¥199/年（早鸟 ¥99），月费 ¥19
理由：BestBlogs 把 $20→$9.9 砍半说明中文月费敏感；年费降低决策频率、提高 LTV。一次性"早鸟买断/赞助"可作冷启动。
D5技术栈？
推荐：TypeScript 全栈（Next.js + Node Worker）
理由：单人/小团队一套语言效率最高；社区与 AI 辅助成熟。BestBlogs 用 Java/Spring 亦可，但对你不是最优。
D6主存储？
推荐：PostgreSQL + pgvector（关系+jsonb+向量一体）
理由：少一个组件、运维简单、事务清晰。BestBlogs 用 MongoDB+ES，规模化后可引入 ES 作搜索读模型。
D7LLM 分析编排？
推荐：MVP 直连 SDK + 轻量编排；prompt 难调时再上 Dify
理由：BestBlogs 用 Dify 自部署便于调 prompt；但起步直连更轻。分级调用：小模型初评 + 中端模型分析。
D8精审机制？
推荐：MVP 由你本人精审高曝光/低置信内容，后续半自动→社区化
理由：精审是判断力来源，初期必须亲自做；这也是你"评分标准"的训练过程。
D9多垂直如何演进？
推荐：架构按"共享核心 + 垂直 lens"预留，业务先做穿 1 个垂直再扩
理由：数据层共通（采集/实体/基础分析算一次），判断层按垂直分开。先专注一个建判断力与信任，再低边际成本加垂直 + 做跨垂直综合。
D10北极星指标？
推荐：深度阅读闭环率（点入详情且读完/触发 AI 伴读的周活占比）
反指标：不优化阅读时长、内容数量、无深度 DAU。继承 BestBlogs"让你读得更少"的哲学。

1最终定位

一句话定位：「码间精选」是面向中文开发者的 AI Coding 领域高质量阅读工作流——每天替你判断"这个领域值得读什么"，生成个性化早报，并让人和 AI Agent 都能调用这份判断。
🧭

母句（信念）

让高质量内容找到对的人——在 AI Coding 这个最快变化的领域里。

🎯

用户主张

"AI Coding 每天值得读的，我已替你判断好。读得更少，但更对。"

🏗️

结构

公共策展建信任 → 个性化工作流驱留存 → 可调用 API 打开天花板。

定位继承 BestBlogs 的三层结构与产品哲学，但收窄到一个垂直做深，并把"Agent 可调用"从长期方向提前为一等公民（差异化）。

2目标用户与问题

目标用户

  • 核心：用 AI 写代码 / 做 Agent 的中文开发者、独立开发者、技术 leader
  • 扩展：关注 AI 工程化的产品/研究者；用 Claude/Cursor 的重度用户
  • 共性：英文源读不过来、信息过载严重、付费力强、最早采用 Agent 工具

解决的问题（继承 BestBlogs 三问）

  • 发现与判断：AI Coding 日更爆炸，判断"值不值得读"成本高于获取
  • 吸收效率：长文/英文太多，需先压缩+排序再决定深读
  • 沉淀缺失：读过即忘，缺持续跟踪与复用机制

3产品形态：双产品 + 共享核心

产品二
Agent 策展 API / MCP
把"今日精选/检索/深度分析"开放为稳定原语 + MCP 工具，供 Claude/Cursor/自建 Agent 调用。复用同一份数据。
产品一
垂直 AI 策展阅读 Reader（先做）
Web 端：公共精选 + 我的早报 + 为你推荐 + AI 伴读 + 账户/Pro。承接获客、留存与付费。
共享核心
内容中台 + 垂直判断层
采集 → 内容实体（全局唯一、去重）→ 基础分析（算一次）→ 垂直评分（content×vertical，每垂直一份）。两产品共用。
核心原则（来自上一轮结论）：一条内容唯一，基础分析算一次；"它对某垂直的价值"是 content × vertical 的每垂直一份。采集+实体+基础分析共通（成本优势与跨垂直综合能力来源），判断+分发按垂直/产品分开（护城河）。详见两份《开发架构》。

典型用户旅程（一天）

  • 工作间隙：打开为你推荐，发现一篇 Agent 评测实战，开 AI 伴读快速理解，收藏

7差异化与护城河

差异化（vs BestBlogs / 竞品）

  • 更垂直更深：只做 AI Coding，比泛技术策展更懂黑话与价值
  • Agent-first：把 MCP/API 提前为一等公民（BestBlogs 第三层尚浅）
  • 判断前置：AI 判断"值不值得读"，而非只做"读得快"（vs Feedly/Readwise）

护城河（随时间复利）

  • 领域评分标准 + 标签体系：沉淀在 rubric 与精审里，无法一次性抄走
  • 你本人的领域信誉：判断力的根
  • 个性化迁移壁垒：越用越准
  • 结构化数据 + Agent 生态卡位

9商业模式与定价

Free 高质量公共入口

  • 公共精选 + 公共早报
  • 基础发现与详情
  • 有限 AI 伴读（每日 N 次）
  • 作用：建立"我懂 AI Coding"的信任

Pro 个性化工作流（¥199/年）

  • 我的早报 + 为你推荐
  • 完整 AI 伴读 + 私有源
  • 回顾沉淀（V2）
  • 定价：早鸟 ¥99/年 · 月费 ¥19 · 待确认 D4

增长漏斗：公共策展获客 → 首次"我的早报"激活（感受"懂我"）→ 工作流留存 → Pro 付费 → 第三层扩展。开发者侧：产品二 API 用量/订阅作第二曲线。

12风险与红线

风险应对
LLM 成本小模型初评 + 缓存 + 只对高价值内容深分析；MVP 月成本控 $60-300
内容源封锁/版权只存摘要+分析+链接（不全文转载），标注来源，多源冗余
通用 AI 替代护城河是持续判断标准+追踪+源质量，非单次摘要
单人断档自动化 + 早报/精审可委托流程化
合规（中文）内容审核、ICP 备案、数据隐私
红线（继承 BestBlogs 的克制）：不以时长为目标、不做泛化 AI 工具箱、不以内容数量取胜。产品价值 = 帮用户读得更少但更对，把时间还给他们。
